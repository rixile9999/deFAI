deFAI 연합 학습 환경 평가

① 계층 구조 · 매칭 누가 어느 엣지에 배정되고, 그 매칭이 잘 되고 있나

계층적 학습 환경 tree

서버→엣지→클라이언트 배정, 엣지별 반영/배정 수, 진회색 = 타임아웃 · 빨강 = 이상치 → 병목이 생긴 엣지

우선순위 rank

품질 Q 순위의 라운드별 변화 → 꾸준한 상위 클라이언트, 순위가 급락한 클라이언트

매칭 training trend

재매칭(세로선, ↺ 재배정 수) 뒤 엣지별 평균 품질 → 매칭 효과, 뒤처진 엣지 (클라이언트 강조 = 그 클라이언트 품질)

매칭 행렬 (faceted grid)

재매칭 라운드별 클라이언트 × 엣지: 점 = 배정(엣지 색), 검은 테두리 = 재배정, 파랑 농도 = 이익 → 재배정이 줄며 수렴하는지, 이익이 낮은데 배정된 클라이언트

매칭 outlier detection

엣지 동료 대비 품질 저하 z, 빨강 = z>3 → 재매칭·제외 후보 클라이언트

② 통신 상태 어느 링크가 느리거나 끊기고, 트래픽은 어디로 흐르나

통신 환경 hyperbolic

tree 와 같은 구조를 링크 지연(파랑 농도)으로, 진회색 = 타임아웃 → 느리거나 끊긴 경로 (클릭 = 초점 이동)

서버 통신 상태 (pixel-based)

엣지·클라이언트 × 라운드의 지연·상태·업로드 → 지연이 점점 커지는 클라이언트, 타임아웃이 반복되는 구간과 엣지

서버 통신 상태 (parallel)

클라이언트별 대역폭·지연·타임아웃·참여율·이상치·품질의 관계, 빨간 선 = 이상치가 나온 클라이언트 → 축을 끌어 '느리고 자주 끊기는' 집단 선택

네트워크 트래픽 (sankey)

클라이언트→엣지→서버 누적 전송량 → 트래픽이 몰리는 엣지, 못 보내는 클라이언트

③ 데이터 · 클라이언트 학습 데이터 분포 차이가 클라이언트 학습 결과로 어떻게 이어지나

데이터 비율 · 엔트로피 heatmap

숫자 구성비(파랑 농도)·데이터 비율 p·엔트로피 H → 데이터가 치우치거나 적은 클라이언트

클라이언트 학습 비교 (cluster · matrix)

업데이트가 비슷한 클라이언트 군집(왼쪽)과 군집별 라운드 학습 진행(오른쪽) → 같은 데이터 분포 집단, 학습이 느리거나 불안정한 집단

연합 모델 평가

업데이트 코사인 유사도 군집·연결망 → 비슷한 분포 집단, 고립된(이질적인) 클라이언트

클라이언트 로그 (sparklines table)

클라이언트별 정확도·지연·품질 추이와 타임아웃·이상치 횟수 → 문제를 반복하는 클라이언트를 표에서 바로 찾는다

④ 전역 모델 · 알고리즘 비교 · 비용 전체 성능, 알고리즘 간 차이, 자원·통신 비용

training trend · outlier

전역 정확도·하위10% 클라이언트와 라운드별 이상치(빨강)·타임아웃(진회색) 수 → 하락 원인, 정체

알고리즘 정확도 비교

세 알고리즘 곡선(띠 = seed 범위) → 더 빨리·높게 수렴하는 쪽

알고리즘 지표 비교

평균·하위10% 클라이언트·최저 숫자 정확도 → 성능과 공정성 차이

클라이언트 기여도

전역 모델에 반영된 기여 → 소수가 학습을 좌우하는지(80% 선), 기여가 끊긴 클라이언트
